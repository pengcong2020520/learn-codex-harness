# 布局排版校验

任何线框、主题样页、高保真原型，包括首版与每次改版，都要先通过布局校验才能给用户看。沿用 [总流程](../agent-design-flow/SKILL.md) 的 `design-outline`、section 和定位 hash；布局校验不替代流程交互验证与用户确认。

## 执行与停止条件

1. 检查最终单文件，按大纲遍历所有 `(screen,state)`，不带 `auto=1`。Web 默认检查 1440×900、1280×720；屏幕 id 以 `app-` 开头时检查 390×844。可选平铺模式不用于一屏验收。
2. 工作室运行时用 `check_design` 工具（K3a-2 提供）；开发侧从仓库根目录运行 `node app/scripts/layout-check.mjs <html> [--viewports 1440x900,1280x720] [--json 报告路径]`。需要本机 Chrome 或 Chromium，可用 `CHROME_PATH` 指定路径。工具缺失或环境不允许执行时写“未验证”并说明原因，不能声称已通过。
3. 检查整页滚动、hidden/clip 文字截断（超出 1px）、可见文字叶子重叠（交集大于 4px²）、字号小于 11px（警告）、超出视口、跳转目标、大纲与 section 双向对应、控制台错误与 file/data/blob 以外请求。区域内滚动允许；不得用隐藏、删掉内容或缩到小字号来掩盖错误。
4. 发现错误就修，修完再查，最多自动修 2 轮。每轮保存新版本与对应报告，定位到具体屏、状态、视口和元素。还有错误时如实告诉用户剩下哪些问题，不能声称已通过或作为合格产物交付；警告也随报告说明，必要时请用户决定。
5. CLI 有错误返回 1，检查本身无法运行返回 2；仅警告返回 0。按退出码与报告核对是否完成，未运行不能写成 0 错误。

## 常见问题的修法

- 长文本截断：允许换行，用 `overflow-wrap` 处理长词，调整容器高度；确需长内容时放进区域内滚动，不用省略号掩盖验收内容。
- 定宽容器溢出：改成受视口约束的宽度，核对 padding 和 `box-sizing`；flex/grid 子项按需要设置 `min-width: 0`、`min-height: 0`。
- 绝对定位重叠：优先用正常文档流、flex 或 grid；必须叠放的控件留出实际占位和间距，核对不同视口与长文案。
- 一屏放不下：固定外层到视口，把列表、预览、聊天等长内容放进区域内滚动，保留目录与核心操作可达；不靠整页滚动或缩小字号解决。
- 字号过小：至少恢复到 11px，重新分配空间，复查排版；警告不能静默丢掉。
- 跳转或大纲不一致：逐项修正 screen、state、group 与按钮 hash，保留用户确认的页面和状态，不删掉失败用例。
- 控制台错误或外部请求：修脚本，内嵌离线资源，使用系统字体，核对所有入口和异常状态。
