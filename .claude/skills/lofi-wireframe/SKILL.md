# 低保真线框

## 用户提示词原文

（用户提供、已实测的提示词原文）
根据当前项目已经写好的 PRD，梳理产品的完整核心交互流程，并生成一份低保真线框图，最终输出为一个单页 HTML 文件。

要求：
1. 只做低保真，不做正式 UI。使用黑白灰、基础框线和图片占位块，只表达信息层级、核心文案、按钮位置和页面状态；
2. 按照用户真实使用产品的先后顺序分组，把 PRD 中涉及的核心页面和关键状态全部平铺在同一页，让我可以从头到尾检查整个流程；
3. 每一屏都标清页面名称、它在流程里的位置、用户可以执行的操作，以及操作之后会进入哪个页面或状态；
4. 除了正常流程，还要补齐 PRD 中涉及的首次使用、权限申请、加载中、无数据、失败和异常恢复等状态；
5. 不要擅自增加 PRD 里没有的功能。PRD 中没有说明清楚的地方单独标成「待确认」，不要自行补全；
6. 所有内容放在一个 HTML 文件里，打开文件就能完整查看。

## 执行补充

输入是最新已确认 PRD（初版 `prd-v1.md`），输出 `outputs/design/<项目 id>/wireframe-v1.html`，之后按版本递增。先把 PRD 页面清单和核心流程映射成组、屏、状态，再绘制；不得用一个示意页代替完整流程。

HTML 必须是可离线打开的单文件，只用系统字体栈。每屏使用 `<section data-screen="<id>" data-state="<状态>" data-group="<分组>">`；支持 `#screen=<id>&state=<状态>` 只显示对应屏，且监听地址变化。内嵌 `design-outline`（`application/json`），结构与总流程一致。固定状态词表为 default、first-use、permission、loading、empty、error、recovery；自定义状态列入大纲。工作室中嵌入预览，不截图。

Web 每屏宽 1280px，App 每屏宽 390px，均用设备外框表示；双端分别绘制并加 `web-` / `app-` 屏幕 id 前缀。宽屏总览可以横向滚动或等比缩放，不能通过缩小内容宽度改变验收尺寸。页面顶部放分组与顺序的流程总览，顺序与大纲一致，点击可定位到屏幕。

每屏统一标注「页面名称｜端｜组内位置｜当前状态」，下面列「用户可执行的操作 → 目标页面 / 状态」。操作目标以定位 hash 写进大纲的 `actions[].to`；没有后续跳转的动作说明当前屏的结果状态。装饰不用真实图片，保留黑白灰与占位块。

PRD 已完整，原则上不出现待确认；若确实遗漏，严格执行原文第 5 条，单独标「待确认」并说明受影响的屏和操作，不自行补全、不暗改 PRD。先回到 PRD 澄清、生成新版本并获确认，再补齐线框；有此缺口时不能确认线框进入主题阶段。

核对每个 PRD 页面、分支和状态都有对应屏，标注、按钮去向、大纲与实际 section 一致。工作室内用嵌入预览逐步展示，用户确认后进入主题。
