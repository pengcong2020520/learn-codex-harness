# 把本地 Agent 部署到生产

以下路径和命令均相对于 `app/`；先进入 `app/`。先读 README「部署到服务器」「域名与 HTTPS」「备份与恢复」「配置项参考」「打开集群」，以及目标 Agent 配置。

1. 运行 `npm run production:check`，逐项解释每个 `✗`（必须处理）和 `!`（建议），明确 `✓` 只代表该静态检查通过。命令不探测或启动服务，不能据此宣布部署已就绪。
2. 一次确认部署形态：有没有服务器、有没有域名、是否希望使用自己的数据库。当前只支持脚手架自带数据库；外部数据库接入是计划中的功能，不要假装支持或擅自改 Compose。已有服务器且接受自带数据库时，按 README「部署到服务器」操作；远端需先具备该章节列出的工具，脚本不会代装。
3. 在动线上服务器之前，把具体命令、影响范围和回滚方法告诉用户，等待确认。部署中断或状态不明时停下核对，不自动重试。代码和镜像的 `rollback` 不回滚数据库。
4. 逐项处理：
   - 域名与 HTTPS：按 README「域名与 HTTPS」配置 DNS、宿主反向代理与证书、允许的来源。白名单不等于证书或公网代理已配置；宿主端口继续只发布到回环地址。
   - 创建用户：在目标部署目录运行 `npm run user:add -- <用户名>`，让用户自己在终端输入密码。远端操作也可用 README 所列 `deploy` 的 `user` 子命令。
   - 备份与恢复演练：运行 `npm run backup`，安排定时备份；按 README「备份与恢复」在独立环境使用 `npm run restore -- <备份目录名>` 演练，先说明恢复会覆盖目标数据，不能拿线上数据试验。
   - 预算上限：按 README「配置项参考」选定每日或每月 token、金额预算，由用户在终端填写；不擅自指定预算数值。
   - 备用模型：核对 `config/models.json` 的 `fallbacks`、用途和能力，提示用户在终端填写备用服务商 Key；填写非空不等于调用成功。
   - 集群：根据用户对故障接管的需求决定，需扩容时按 README「打开集群」运行 `npm run cluster:enable`。同机多容器不能保证宿主故障时可用。
5. 部署后在实际部署目录再运行 `npm run production:check`，并通过真实入口做一次登录和对话验证。认证由用户在终端完成；对话验证需确认模型调用范围。分别报告已通过、待处理和未验证项，不把静态检查当作真实验证。

边界：不读取、不打印 `.env`，通过检查命令了解状态；不在对话里索要或回显密钥和密码。需要配置时请用户自行在终端输入。不改内核或数据库迁移来绕过当前部署限制，不默认删除数据卷。
