# s04 · 可执行机制实验

在本阶段目录使用 Node.js 24+；已安装依赖后运行：

```sh
npm run lesson -- list
npm run lesson -- s04-queue
```

每课先输出学习问题、真实校验命令、预期观察、原因和证据边界，再运行本目录的模块测试。预期观察不是成功宣告；以 Node 测试报告的 pass / fail / skip 为准。参数只接受列出的课时 ID，不接收任意 shell。

| 课时 | 要验证的问题 | 运行方式 |
| --- | --- | --- |
| s04-queue | 模型还在回答，又连着提交了两条，服务端怎么保证不丢、不乱序、不并发？ | `npm run lesson -- s04-queue` |
| s04-reconnect | SSE 连接断了又连上，客户端会漏掉中间的状态，或者把旧消息再发一遍吗？ | `npm run lesson -- s04-reconnect` |
| s04-restart | 服务重启时有一条在执行、一条在排队，重启后会怎样？ | `npm run lesson -- s04-restart` |

离线实验使用临时目录、假 RPC 或本地协议进程，调用真实服务模块并执行 assert；不读取本阶段的 .env、不连接外部模型。子测试只继承系统路径与临时目录环境，不继承提供商凭据。测试结束清理自己创建的临时文件。

## s04-queue · 排队搬到服务端

输入先写进任务记录，再由调度器按会话逐条发出；执行顺序不再依赖客户端在线。

观察：提交立即返回 queued，不等模型回复；同一会话先进先出，每条是一个新的 turn，同时只跑一轮；客户端退出后，已提交的消息由服务端继续执行。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。

## s04-reconnect · 断线重连，事件不丢不重

快照兜住断线期间的变化；提交和订阅是两件事，重连永远不会重发。

观察：每次连接先收到一份完整快照，之后才是增量事件；重连只是重新订阅，不会产生新的消息；事件只推给对应 Thread 的订阅者。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。

## s04-restart · 重启以后，哪些任务还能继续

结果不确定的执行宁可停下来等人核对，也不重复执行。

观察：排队中的消息保留下来；执行中的消息标为 unconfirmed，队列暂停，不自动重发；/continue 明确继续后才处理下一条，不重跑失败项。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。
