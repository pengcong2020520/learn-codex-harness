# s03 · 可执行机制实验

在本阶段目录使用 Node.js 24+；已安装依赖后运行：

```sh
npm run lesson -- list
npm run lesson -- s03-resident
```

每课先输出学习问题、真实校验命令、预期观察、原因和证据边界，再运行本目录的模块测试。预期观察不是成功宣告；以 Node 测试报告的 pass / fail / skip 为准。参数只接受列出的课时 ID，不接收任意 shell。

| 课时 | 要验证的问题 | 运行方式 |
| --- | --- | --- |
| s03-resident | 终端客户端在回复途中被关掉，服务端那一轮会被取消吗？ | `npm run lesson -- s03-resident` |
| s03-one-turn | 上一轮还没答完就再发一条，服务端会怎么处理？ | `npm run lesson -- s03-one-turn` |
| s03-cleanup | 服务常驻后每次启动都留下 .runs/app-server-*，能直接按时间全删吗？ | `npm run lesson -- s03-cleanup` |

离线实验使用临时目录、假 RPC 或本地协议进程，调用真实服务模块并执行 assert；不读取本阶段的 .env、不连接外部模型。子测试只继承系统路径与临时目录环境，不继承提供商凭据。测试结束清理自己创建的临时文件。

## s03-resident · 客户端断开，这一轮还在跑

一轮由服务端发起并持有；客户端只是查看者，断开不影响执行。

观察：POST /turns 立即返回 202 和 turn id，不等模型答完；客户端进程被杀掉后，服务端这一轮照常完成；重新连接后用 /sessions/resume 能看到完整回复。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。

## s03-one-turn · 一次只跑一轮，服务端还不排队

本阶段服务端只负责发起与查看；排队调度要等下一章的任务队列。

观察：同一会话上一轮未结束时，再提交返回 409；并发提交只有一个真正发出 turn/start；客户端自己等上一轮结束，再发下一条。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。

## s03-cleanup · 运行目录怎么清理才不误删

运行目录是缓存，但会话检索和正在运行的进程依赖它；先保住索引、再确认无人使用才删除。

观察：只清理超过 7 天且不在最近 5 次之内的运行目录；当前运行、已加载会话、活进程和正在打开的文件都受保护；删除前先把会话索引落盘，删掉日志后历史会话仍能检索。

边界：离线临时目录与真实服务模块；Codex 是 stdio 假进程或 fixture，不调用模型。真实项目 .env 不会被读取。
