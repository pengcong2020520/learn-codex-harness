s17

分片与路由：按用户分布，从任意入口找到他

用户先归分片，分片再归节点；请求核对路由，数据库核对写权，搬家前先停写。

分片键是用户，不是消息

上一章的云端 Agent 有三个节点，却只有 control 干活，用户多了仍是一台装不下。本章把用户分到不同节点，让每台都工作；入口还要能找到用户，不能把请求随意交给一块没有他历史的磁盘。

从 s14 起，历史、索引和记忆都保存在用户自己的 CODEX_HOME。若第一轮在 A、第二轮在 B，B 看不到前文。所以分片键取稳定的用户 ID，一个人的全部会话与原生状态跟着他落在同一主节点。

用户先属于一个分片，再由分片找到主节点。control 发布归属，主节点运行用户业务；两种职责不同。三个节点各用自己的磁盘，仅部署身份一致，PG 中有会话索引不等于其他节点已有原生文件。

租约、任期、用户隔离和 Hub 权限继续生效。分片负责放置与寻找数据，不替代认证授权，也不改变 Codex 的执行循环。

用户归分片，分片归机器，两步分开

分配策略只决定用户属于哪个分片，control 再决定分片在哪台机器。两步分开，换机器不必重新计算每个用户的归属；个别用户还能有 override 例外记录，供手动迁移使用。

默认把用户 ID 哈希到 64 个槽，再按 slot % 3 分到三个分片，槽数为 22、21、21，不保证任意三个用户正好均匀。范围策略按 ID 前缀划分，直观但易冷热不均；改变策略本身不会搬走已有数据。

每个节点缓存一份路由表，避免每次请求都查 etcd。启动整表读取 shards、slots、overrides，记录共同 revision，再用 Watch 增量更新；断线或版本压缩后重读，每 5 秒对账。快照期间的新事件要重放，不能被旧快照覆盖。

Watch 快不等于所有节点同时更新，请求仍要核对版本。主节点离线时保留它的归属并返回不可用；磁盘没有复制过去，改个节点名不能完成接管。

任意入口转发，主节点再核对一次

路由让用户不必知道自己在哪台机器。任意就绪节点都可作为入口，先认证用户，再按缓存转发给主节点；接收方重新认证用户与调用节点，不能因为“来自集群”就信任身份和权限。

接收方核对两件事：自己仍是该用户的主节点，自己的缓存 revision 不落后于请求携带的 revision。任一不满足返回 409 STALE_ROUTE；不是无条件拒绝版本较旧的转发请求。

export async function routedRequest({ cache, userId, nodeId, members, local, remote }) {
  for (let attempt = 0; attempt < 2; attempt++) {
    const route = cache.routeOf(userId), address = targetOf(route, members);
    try {
      const result = route.primary === nodeId ? await local(route) : await remote(address, route);
      if (result?.status === 409 && result.headers?.get('x-cluster-error') === 'STALE_ROUTE') {
        await result.body?.cancel(); throw staleRoute();
      }
      return result;
    } catch (error) {
      if (error.code !== 'STALE_ROUTE' || attempt === 1) throw error;
      await cache.refresh();
    }
  }
}

主节点核对归属与 revision；仅 STALE_ROUTE 允许 refresh 后再试一次，普通业务 409 不触发重试。

数据库按分片隔离写入

路由决定请求往哪走，数据库决定谁有权写。用户迁走后，旧节点可能还有后台任务，因此业务写入也要携带节点身份与分片任期 epoch；不匹配就以 SH001 拒绝。

派发前还要同时确认租约、缓存归属和 PG 用户映射，并且用户未暂停。一个用户迁移时，只暂停他，其他用户继续工作。

CREATE OR REPLACE FUNCTION agent_data.check_shard(owner uuid) RETURNS void
LANGUAGE plpgsql SET search_path=pg_catalog,agent_data AS $$
DECLARE actual record; supplied text := current_setting('app.node',true);
BEGIN
 -- Lock BOTH mappings until commit: migration cannot overtake an old owner's transaction.
 SELECT s.node_id,s.epoch,u.shard_id,u.paused INTO actual FROM user_shards u JOIN shard_owners s USING(shard_id)
 WHERE u.user_id=owner FOR SHARE OF u,s;
 IF actual IS NULL OR (actual.paused AND EXISTS(SELECT 1 FROM move_operations WHERE user_id=owner AND state IN ('copying','copied','switched','failed'))) OR actual.node_id IS DISTINCT FROM supplied OR
    actual.epoch::text IS DISTINCT FROM nullif(current_setting('app.shard_epoch',true),'') OR
    current_user <> 'agent_' || replace(supplied,'-','_') THEN
  RAISE EXCEPTION 'missing, foreign or stale shard owner' USING ERRCODE='SH001', DETAIL=json_build_object(
    'ownerId',owner,'shardId',actual.shard_id,'primary',actual.node_id,'epoch',actual.epoch::text,
    'nodeId',supplied,'suppliedEpoch',current_setting('app.shard_epoch',true))::text;
 END IF;
END $$;

export async function shardFailure(error, generation, origin, statement) {
  if (error.code !== 'SH001' || error.shardDiagnostic) return;
  // The rejected ROW is authoritative. Requester identity alone cannot identify its shard.
  const row = rowFenceDetail(error), owner = row.ownerId;
  let before, after, refreshFailed = false;
  try { before = owner && generation.routes?.routeOf(owner); } catch {}
  try { await generation.routes?.refresh(); after = owner && generation.routes?.routeOf(owner); }
  catch { refreshFailed = true; }
  const believedPrimary = before?.primary === generation.nodeId;
  const isolate = believedPrimary && (refreshFailed || after?.primary === generation.nodeId);
  error.shardDiagnostic = { ownerId: owner || null, believedPrimary, refreshFailed, isolate };
  logFailure(error, generation, origin, statement, 'SH001', {
    classification: isolate ? 'stale-primary' : believedPrimary ? 'ownership-moved' : owner ? 'wrong-shard-write' : 'unknown-row-owner',
    rowRouteBefore: before || null, rowRouteAfter: after || null, ...error.shardDiagnostic,
  });
  if (isolate) generation.isolate?.(refreshFailed ? 'shard-refresh-failed' : 'database-stale-shard');
}

迁移：先停写，再搬家

搬家时数据不能还在变化。手动迁移先暂停新任务，等执行中的轮次结束并关闭用户进程，再复制 CODEX_HOME 和工作目录，切换归属后才恢复派发。

control 创建持久操作单，绑定用户、源目标、调用节点和 30 分钟有效期。内部步骤按单据核对身份与状态，节点密钥不能授权任意搬动他人的目录。

export async function authorizeMove(pool, { operationId, userId, caller, receiver, step, target }) {
  if (!/^[a-f0-9]{8}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{4}-[a-f0-9]{12}$/.test(operationId || '')) throw denied();
  const op = (await pool.query('SELECT * FROM agent_data.move_operations WHERE id=$1 AND expires_at > now()', [operationId])).rows[0];
  const states = { pause: ['paused'], drain: ['paused'], copy: ['copying'], transfer: ['copying'], content: ['copying'], resume: ['switched'] };
  if (!op || op.user_id !== userId || !states[step]?.includes(op.state)) throw denied();
  const data = ['transfer','content'].includes(step);
  if (caller !== (data ? op.source_node : op.control_node) ||
      (step === 'resume' ? ![op.source_node, op.target_node].includes(receiver) : receiver !== (data ? op.target_node : op.source_node)) ||
      (target !== undefined && target !== op.target_node)) throw denied();
  return op;
}

export async function moveUser({ userId, shardId, control, pause, drain, copy, resume }) {
  if (!SHARDS.includes(shardId)) throw new Error('分片必须是 0、1、2。');
  const term = control.coordination?.term();
  const op = await control.beginMove(userId, shardId);
  if (!op) return { unchanged: true };
  try {
    await pause(op.source_node, userId, op.id);
    await drain(op.source_node, userId, op.id);
    await control.advanceMove(op.id, 'paused', 'copying');
    await copy(op.source_node, op.target_node, userId, op.id);
    await control.advanceMove(op.id, 'copying', 'copied');
    await control.switchUser(userId, shardId, op.id);
    await resume(op.target_node, userId, op.id);
    await resume(op.source_node, userId, op.id);
    await control.finishMove(op);
    return { userId, from: op.from_shard, shardId, operationId: op.id };
  } catch (error) {
    // Never revive an old disk after an uncertain COMMIT or publish; retain both copies for recovery.
    await control.failMove(op.id, term).catch(() => { error.rollbackFailed = true; });
    throw error;
  }
}

const skipTop = process.argv[3] === 'home' ? new Set(['tmp']) : new Set();
function inspect(target, top = false) {
  const s = fs.lstatSync(target);
  if (s.isSymbolicLink() || (!s.isDirectory() && !s.isFile()) || (s.isFile() && s.nlink !== 1)) throw new Error('迁移拒绝链接和特殊文件。');
  if (!(kind === 'workspace' ? [0, uid] : [uid]).includes(s.uid) || ![uid, 1000].includes(s.gid)) throw new Error('迁移属主不匹配。');
  if (s.isDirectory()) for (const name of fs.readdirSync(target)) {
    if (top && skipTop.has(name)) continue;
    if (name === '..' || /[\x00-\x1f\x7f\\]/.test(name)) throw new Error('迁移文件名含控制字符。');
    inspect(path.join(target, name));
  }
}

每次接收默认最多 1 GiB，只能下调；落盘前检查至少两倍配置上限的空间。空间不足返回 507，流超限返回 413，清理临时文件。归档先校验，再在同挂载的暂存目录恢复权限和属主，最后发布，避免混合 SQLite 文件。

export const MAX_TRANSFER_BYTES = 1024 ** 3;
export function transferLimit(env = process.env) {
  const value = env.AGENT_TRANSFER_MAX_BYTES === undefined ? MAX_TRANSFER_BYTES : Number(env.AGENT_TRANSFER_MAX_BYTES);
  if (!Number.isSafeInteger(value) || value < 1 || value > MAX_TRANSFER_BYTES) throw new AppError('AGENT_TRANSFER_MAX_BYTES 只能下调且必须为正整数。', 503);
  return value;
}
export function assertTransferSpace(directory, limit, statfs = fs.statfsSync) {
  // Inspect the nearest existing ancestor before creating destination directories/files.
  while (!fs.existsSync(directory)) directory = path.dirname(directory);
  const stat = statfs(directory, { bigint: true });
  if (BigInt(stat.bavail) * BigInt(stat.bsize) < 2n * BigInt(limit)) throw new AppError('目标卷可用空间不足两倍传输上限。', 507);
}
export function limitTransfer(limit = transferLimit()) {
  let bytes = 0;
  return new Transform({ transform(chunk, encoding, callback) {
    bytes += chunk.length;
    callback(bytes > limit ? new AppError('迁移内容超过接收上限。', 413) : null, bytes > limit ? undefined : chunk);
  } });
}
export const restoredMode = (mode, directory) => mode & (directory ? 0o2777 : 0o777);

  async switchUser(userId, shardId, operationId) {
    const term = this.coordination.term();
    try {
      await this.locked(async db => {
        const op = await this.#advanceMove(db, operationId, 'copied', 'switched');
        if (op.user_id !== userId || op.to_shard !== shardId) throw new AppError('操作单用户或目标不匹配。', 403);
        const result = await db.query('UPDATE agent_data.user_shards SET shard_id=$2 WHERE user_id=$1 AND shard_id=$3 AND paused RETURNING user_id', [userId,shardId,op.from_shard]);
        if (!result.rows[0]) throw new AppError('源分片或暂停状态变化。', 409);
      }); // COMMIT must complete before publishing the override.
      await this.coordination.guardedPut(OVERRIDE_PREFIX + userId, JSON.stringify(shardId));
      await this.cache.refresh();
    } catch (error) {
      await this.failMove(operationId, term).catch(() => { error.rollbackFailed = true; });
      (this.log || console.error)(`迁移切换失败，用户保持暂停: operation=${operationId}, user=${userId}`);

    }

源码解读

copied → switched 与 PG 用户归属在同一任期事务内提交，之后才发布 etcd override；失败记录操作单并保持暂停。

PG 与 etcd 没有跨库原子提交。发布或收尾失败就保持暂停，保留两份磁盘，以实际数据库状态为准核对，不自动回退；即使 COMMIT 回复丢失，也不能推断提交没发生。

迁移成功要用同一用户继续同一会话来验证。源目标必须在线，源磁盘已坏时，手动迁移不能凭空恢复历史。传输与故障核对细节见设计说明。

共享知识只有一份，一台坏了只影响它那一片

用户分开存放后，共享知识库仍只有所有者主节点上的一份权威内容。接收者节点先问 Hub，再带着用户令牌访问所有者主节点；后者重新认证并检查授权，才通过只读接口交出内容，中途撤销也不能被缓存放行。

源码解读

先拒绝自报 requester，再认证终端用户令牌；以认证身份取得新的 Hub 快照，并核对路由、暂停和读取权限。

后续读取可复用内存中的最近认证令牌，但令牌不写入任务或磁盘；重启后缺令牌就拒绝跨分片读取。RAG 查询在请求者节点生成 embedding 并按请求者计费，内容仍由所有者节点读取。

一台节点停止，只让它负责的分片返回 503 和原因，其他分片照常服务。重启要核对不确定任务，不自动重跑。策略、路由、拒写与迁移实验见本章 README；真实 PG、etcd、Linux uid 和原生续聊需分别验收。
