协调面：租约判断谁活着，任期决定谁说了算

分不清慢和死，就用共同规则判断成员资格；旧主醒来，也不能凭过期任期继续写入。

分布式里，分不清“慢”和“死”

上一章的云端 Agent 已能让多人安全共用，但只有一台机器，停了就一起停。扩展到多台之前，先要回答谁还活着、谁有权服务：节点没响应，可能是故障，也可能只是网络慢。

如果把慢误判为死，选出了新主，旧主醒来后又继续写，就会出现两个主同时工作的脑裂。因此成员资格交给所有节点共同认可的lease，完整业务由当选的control负责，另外两个节点热备，随时准备接任。

etcd 只保存成员、选举与任期等协调信息；业务会话和任务仍在 PostgreSQL，Redis 唤醒队列，Codex 执行轮次。入口只转发给就绪的 control，用户隔离与 Hub 授权继续生效。

本章三个容器共享数据卷，只用于单机主备模拟，并非三个独立故障域。PostgreSQL、Redis、模型网关和 etcd 仍是单实例；control 能接任，不等于依赖也高可用。

租约：按时续约才算活着

租约把“它活着吗”变成一个共同可查的事实：租约还在，就有成员资格；过期，注册信息自动消失。本章 TTL 为 10 秒，etcd3 按 TTL/3 自动续约；正常下线主动撤销，不必等待到期。

源码 · server/modules/coordination/index.mjs · 第 24–45 行
  async join() {
    if (this.closed || this.alive) throw new Error('节点已关闭或已经加入。');
    const epoch = ++this.generation;
    const lease = this.client.lease(TTL); // automatic KeepAlive, TTL/3, owned by etcd3
    this.lease = lease;
    lease.on('lost', () => { if (this.generation === epoch && this.lease === lease) this.isolate('lease-lost'); });
    lease.on('keepaliveSucceeded', () => {
      if (this.generation !== epoch || this.lease !== lease) return;
      // A delayed reply after a process pause must never revive the old generation.
      if (this.alive && this.now() - this.lastKeepAlive >= TTL * 1000) this.isolate('keepalive-timeout');
      if (this.alive && this.lease === lease) { this.lastKeepAlive = this.now(); this.armDeadline(); }
    });
    lease.on('keepaliveFailed', () => { if (this.generation === epoch) this.checkLease(); });
    await lease.grant();
    if (epoch !== this.generation || lease.revoked() || this.closed) throw notController();
    this.lastKeepAlive = this.now(); this.alive = true;
    this.armDeadline();
    const member = { nodeId: this.nodeId, address: this.address, revision: this.revision,
      agentHash: this.agentHash, capacity: this.capacity, joinedAt: this.clock() };
    await lease.put(MEMBERS + this.nodeId).value(JSON.stringify(member));
    if (epoch !== this.generation || !this.checkLease()) throw notController();
    this.record('joined', { nodeId: this.nodeId });

租约事件带 generation 校验；注册键经 lease.put 写入。

每次加入还有本地代次 generation，旧租约的通知不能影响新代。暂停后迟到的续约成功回包，也不能替旧主续命：单调时钟若已超过 TTL，先隔离。入口与回调都检查这一点，不只依赖可能被延迟的定时器。

源码解读

先快照再 Watch，每 5 秒对账。

Watch 订阅成员变化：先读快照并记录 revision，再从下一版本监听，保留期间到达的更新，避免旧快照覆盖新事实。断线或压缩后重读，每 5 秒对账，补上可能漏掉的变化。

租约到期只说明成员资格失效，不是端到端恢复时限。集群状态里的剩余 TTL 取自 etcd，近期 20 条事件帮助观察过程，但内存事件不等于持久审计。

选举与任期：旧主醒来也写不进去

选举决定谁当 control，任期号证明这份权力属于哪一任。选举记录绑定租约，过期后候选者接任；任期取当选记录的 create_revision，只增不减，不能用时间戳或全局最新版本代替。

源码 · server/modules/coordination/index.mjs · 第 174–186 行
  async elected(campaign, epoch) {
    const key = await campaign.getCampaignKey();
    const { kvs } = await this.client.get(key).exec();
    if (epoch !== this.generation || this.candidate !== campaign || !this.checkLease()) return;
    const kv = kvs[0];
    if (!kv || kv.value.toString() !== this.nodeId || kv.lease !== await this.lease.grant()) throw notController();
    if (epoch !== this.generation || this.candidate !== campaign || !this.checkLease()) return;
    this.electionKey = key; this.ownTerm = kv.create_revision; this.controller = true;
    await this.confirm();
    if (epoch !== this.generation) return;
    this.record('elected', { nodeId: this.nodeId, term: this.ownTerm });
    this.emit('controller', this.ownTerm);
  }

比较选举键和写操作属于同一 etcd 事务。

etcd 的事务只保护 etcd，业务数据库必须另设任期门禁。新 control 先确认选举任期，再推进 PostgreSQL 任期；若库中已有更高任期，返回 CT001 并隔离，不能倒退任期后继续服务。

export async function advanceTerm(pool, generation) {
  assertTerm(generation);
  const origin = new Error('推进数据库任期调用栈');
  try {
    await pool.query('SELECT agent_data.advance_cluster_term($1::bigint)', [generation.term]);
    generation.assert();
  } catch (error) {
    termFailure(error, generation, origin, 'SELECT agent_data.advance_cluster_term');
    throw error;
  }
}

推进数据库任期失败不能继续启动业务。

推进成功后才恢复任务：执行中的轮次标为待核对，不自动重发；queued 重新唤醒。整个恢复过程完成、再次确认控制权后，才开放派发与就绪。启动中失权的迟到回调不能让旧代重新就绪。

数据库也认任期，不依赖旧主自觉停下

旧进程可能仍持有数据库连接，后台写入也不一定经过 HTTP。数据库必须独立核对每笔写入的任期，才能让“旧主醒来也写不进去”成立；这个只增不减的号码就是 fencing token。

锁定当前任期后核对事务任期，缺失或过期抛 CT001。

每笔业务事务携带 app.term，触发器锁住当前任期并比较，缺失或过期都返回 CT001。锁保持到事务结束，推进新任期必须等待旧事务完成，因此推进成功后，不会再有已通过旧检查的事务迟到提交。

源码 · server/modules/data/write.mjs · 第 20–29 行
export function termFailure(error, generation, origin, statement) {
  if (error.code !== 'CT001' || error.termDiagnostic) return;
  let current = true;
  try { generation.assert(); } catch { current = false; }
  const diagnostic = current ? '任期过期或漏传任期' : '任期已失效';
  error.termDiagnostic = { diagnostic, term: generation.term, stack: origin.stack, statement };
  try { (generation.log || console.error)(`[CT001] ${diagnostic}; term=${generation.term}; ${statement}\n${origin.stack}`); }
  catch { /* Logging must not replace CT001 or prevent isolation. */ }
  finally { generation.isolate?.('database-stale-term'); }
}
源码解读

CT001 的诊断不能阻止 finally 中的隔离。

etcd 比较、数据库触发器、本地 generation 各守一个边界：协调信息、业务写入、迟到回调。普通节点不能用自行设置的维护变量绕过数据库检查，维护例外还要求超级用户身份。

旧代只清理自己派发过且仍在执行的任务；若已被新任期拒写，就交给新 control 恢复，不能全局清理并误伤新任务。数据库锁也不能撤销此前已完成的写入。

任期保护不覆盖外部副作用。旧主已经发出的模型和工具调用撤不回，解冻的子进程也可能继续写共享卷。共享卷仅用于本章模拟，独立磁盘和副本还要分别解决数据放置与恢复。

自我隔离：续不上约，就自己停下

节点发现续约失败并超过 TTL，不能等别人通知才停。它立即关闭准入与派发，使就绪变成 503，再关闭用户进程，把执行结果不明的轮次交给待核对流程。

源码 · server/modules/coordination/index.mjs · 第 62–70 行
  isolate(reason) {
    if (!this.alive && !this.controller) return;
    this.alive = false; this.controller = false; this.generation++;
    clearInterval(this.reconcileTimer); clearTimeout(this.watchRetry);
    clearTimeout(this.timer);
    this.lease?.release(); // no more automatic renewals after local fencing
    this.record('isolated', { nodeId: this.nodeId, reason });
    this.emit('lost', reason); // synchronous admission/result fence before any await
  }
源码解读

先清空 alive/controller 并递增代次，同步发出 lost。

隔离先同步让本代失效，清理随后完成；清理慢不是继续接活的理由。重新加入必须等旧业务和用户进程停干净，再领取新租约、订阅和竞选，不能在旧进程未退出时启动第二份。

源码 · server/modules/coordination/rejoin.mjs · 第 15–35 行
  async recover() {
    const c = this.coordination;
    let backoff = 2000;
    while (!this.closed && !c.closed) {
      try {
        await this.service.stop();
        if (this.closed || c.closed) return;
        await c.leaveGeneration();
        if (this.closed || c.closed) return;
        await c.join();
        await c.watchMembers();
        if (this.closed || c.closed) return;
        c.campaign();
        if (!c.checkLease()) throw new Error('campaign lost lease');
        c.record('rejoined'); return;
      } catch {
        c.isolate('rejoin-failed');
        if (this.closed || c.closed) return;
        c.record('rejoin-retry', { delayMs: backoff });
        await this.sleep(backoff);
        backoff = Math.min(30000, backoff * 2);
源码解读

先 stop 和 leaveGeneration，再以新租约加入和竞选。

恢复网络后先作为热备，不自动切回。当选并完成恢复才有机会就绪。热备 /health 可为 200，/ready 为 503；容器用健康判断是否活着，Caddy 用就绪选择服务节点，节点入口仍独立验证任期。

正常停机先停业务，再退出选举和撤销租约；网络分区时撤销可能送不到 etcd，只能停止本地续约、等待远端到期。发送撤销请求不代表删除已经完成。

接任之后，还缺少把负载分出去

主备解决的是故障时谁接任，验证重点应是旧主失权、新主恢复以及待核对任务是否被保留。离线实验核对逻辑分支，真实租约到期、PG 拒写和容器进程关闭仍需外部实验；部署参数与检查步骤见本章 README及设计说明。

停机、备份或恢复必须覆盖三个节点，否则热备可能接任并继续写共享卷。etcd 与 PostgreSQL、外部工具之间没有总原子事务，不能把切换理解成无损恢复所有副作用。
