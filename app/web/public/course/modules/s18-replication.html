副本与故障接管：保留可核对的异步历史窗口

边界快照后继续服务，接管明确接受尾部丢失；epoch 拒绝旧主写入，旧主以副本回归。

先区分业务记录与原生历史

主节点保存着用户的 SQLite、JSONL、记忆与工具产物。业务任务已经写进 PostgreSQL，不代表另一台机器已经有了这些原生历史。副本要回答的第一个问题是“哪些历史已经完整到达”，随后才是“谁能接着服务”。

本章的副本是异步历史窗口，尾部丢失明确接受。主服务继续向前执行，副本只保留最近一次成功提交的边界；主节点故障时，不把尚未复制的历史说成已经恢复。

Codex 负责原生历史与执行循环；worker 负责边界快照与异步发送；store 负责位点、落后统计和任务核对；control 负责接管、发布对账和旧主回归。CODEX_HOME 仍属于各用户的运行环境，副本不改变用户隔离与 Hub 授权。

先固定历史边界，再异步发送

副本是异步历史窗口；暂停新轮次只到本地快照完成，位点只描述快照已经包含的历史。

轮次结束后等待 5 秒合并同用户请求；先关派发、等已进入边界的请求，再检查全部会话。快照生成后立即 release，目标队列和网络耗时不再占用用户暂停。每目标串行、不同目标并行；主节点在成对目录与附属内容校验发布后，以 SH001 保护提交快照位点。发送中有新边界会记脏标记，成功或失败后都再等 5 秒调度；60 秒空闲扫描兜底。

概念职责与边界
边界快照用户全部会话没有执行中轮次时，关闭空闲进程并固定 home、workspace、内容清单和 sequence。
复制位点成功发布后提交的 shard、epoch、sequence 与边界时间，不能取发送结束时的新进度。
异步复制本地快照后释放用户派发，再排队发送；主节点可继续产生尚未复制的尾部。

落后看未复制尾部，不看空闲多久

复制延迟描述尚未复制的已完成轮次；副本落后可以告警，但主节点仍能服务。

落后轮数只计位点之后的 completed；秒数从最早未复制完成轮次起算，无尾部就是 0。超过 300 秒显示 replica_lagging，/ready 保持 200 并附 degraded。README 跨地域实测 RTT 217 ms、约 3 Mbit/s；无限速复制让 /health 首字节延迟 11.6 秒，超过 10 秒租约 TTL。262144 字节/秒的共享限速为控制流留余量；20 MB 全量复制实测约 1 分钟，限速后可能更久。生产必须同地域、同一内网，节点与 PG、etcd、Redis 的往返应不到 1 毫秒。

概念职责与边界
尾部丢失最后成功复制之后的历史可能在主节点故障时丢失，这是明确接受的窗口。
复制限速所有目标的 tar 发送共享本节点字节预算，为租约续约和请求转发留带宽。
replica_lagging未复制尾部等待超过 300 秒、复制错误或未完成传输时暴露的退化状态。

export const LAG_MS = 5 * 60 * 1000;
export function lagOf(row, now = Date.now()) {
  const rounds = Number(row.lag_rounds || 0);
  const seconds = rounds ? Math.max(0, (now - new Date(row.pending_since).getTime()) / 1000) : 0;
  return { ...row, lag_rounds: rounds, lag_seconds: Math.floor(seconds), replica_lagging: Boolean(row.replication_error || row.transfer_started_at) || seconds > LAG_MS / 1000 };
}

replica_ready 表示已建立完整基线，不等于与正在服务的主节点逐字节一致。落后轮数和等待时间反映尾部窗口；副本离线或基线不完整时，即使主节点健康也不能承诺可接管。

网络复制可能持续超过 30 秒。发送每写出一个分块就重置进度计时，连续 30 秒无字节进展才中止；持续有进展的发送没有整体 30 秒上限。复制限速延长网络发送，却不把用户暂停延长到发送结束。

限速延长尾部窗口；跨洋 SQL/etcd 往返仍很慢，放宽超时不能代替同地域部署。

接管先确认副本，再核对三类任务

接管接受尾部丢失；已完成、执行中和排队任务不能用同一种重跑策略。

成员 TTL 为 10 秒。control 发现主成员消失后，检查副本在线、ready、所有用户基线位点及未完成操作单。先在 CT001 事务提交 primary、epoch+1、publishing/recovering，再 guardedPut etcd；发布失败保持封闭并对账补发，不回退 epoch。新主以旧 epoch 位点核对任务：执行中转 unconfirmed 并暂停会话；completed 尾部转 replica_missing；已有会话的 queued 由 outbox 正常首次派发，同会话待核对时先暂停。整会话晚于最后成功复制或整个 home 缺失时，返回 409 REPLICA_MISSING，queued 转 needs-review。只有尾部缺失的会话可保留 rollout 前缀续聊。

概念职责与边界
故障接管副本在线、基线完整且无未完成复制时，由 control 在 PG 事务内更换主并推进 epoch。
replica_ready当前 epoch 已有完整用户基线，不表示每个新轮次都已同步。
replica_missing / unconfirmed前者表示副本缺少已完成结果，后者表示执行结果不明；两者都不自动重跑。

旧主失权后，以副本身份回来

epoch 拒绝旧主写入；旧主以副本回归，完整追平前不能再次接管。

旧主以旧 epoch 写业务或位点，PG 返回 SH001。shardFailure 刷新归属后只停止已失去分片的用户进程，仍可服务其他分片；刷新失败或仍误认为自己是主时隔离。旧主通过 rejoin 回归后，control 将 previous_primary 设为 replica 且 ready=false，新主全量复制全部用户后才确认 ready，不自动切回。手动切换另需持久暂停、等待轮次、最后全量同步，再切换和恢复；同步失败保留暂停，禁止回退 epoch。

概念职责与边界
epoch（分片任期）每次切换单调增加；PG 用当前主节点与 epoch 拒绝旧归属写入。
副本追平旧主回归先 ready=false，由新主为全部用户复制当前 epoch 基线，全部成功后才 ready=true。
SH001 / CT001SH001 保护用户分片业务和复制位点；CT001 保护 control 的协调写入。

从跨地域实测理解生产边界

README 的跨地域实测将控制机放在北京、第二节点放在美东。往返 217 ms、隧道约 3 Mbit/s，停掉主节点后 15 秒内副本接手，已经复制的历史可以续聊。这证明独立磁盘之间能够接管，并不证明该网络适合生产。

观测数字含义
SQL / etcd 单次跨洋调用约 0.45 秒恢复一个会话的几十次往返会累积。
无限速复制时 /health 首字节11.6 秒；租约 TTL 10 秒数据流拥塞足以影响存活判断。
PG 建连1.4–2.8 秒，拥堵时 27 秒网络拥堵会击穿短时限。
会话恢复 / 发消息31 秒 / 39 秒请求能成功仍可能很慢。
全量复制20 MB，约 1 分钟一次真实尾部窗口取决于目录、带宽和轮次。
共享 tar 限速262144 字节/秒原则上不超过实测带宽约 70%，给控制流留余量。

生产必须同地域、同一内网：节点与 PG、etcd、Redis 的往返应不到 1 毫秒。放宽超时只能让跨洋演示工作，不能消除长事务、连接池占用和全量追平耗时。跨地域容灾需要每个地域有独立控制面，再考虑地域之间复制。

本章明确保留控制面单点、每分片一个副本、没有自动再平衡、全量 tar 的 IO 与空间成本。成员身份只认节点名，不验证磁盘是哪一次复制的结果；换盘或恢复备份前必须核对位点，或先以副本身份全量追平。

四个离线实验分别核对边界合并、落后统计、三类任务恢复和旧主停止分片。它们调用生产实现，但不证明真实 PG 触发器、认证 etcd 自然过期时延和 Linux uid 文件访问已经通过。课堂推演是固定教学数据，实际证据来自测试断言与外部验收。
